优先级是根据本地资料与软件开发／Data Science／AI 岗位能力的对应关系作出的整理判断，不是招聘市场统计或命中率预测。这里列问题与复习范围，本轮不逐题生成标准答案。

## 高优先级：先形成通用基础

| 题组 | 来源 | 八股候选问题 | 应达到的程度 |
|---|---|---|---|
| SQL | 751 | 各种 JOIN 有何差异？如何聚合、去重、处理 NULL？如何写存在／不存在查询？ | 能在小表上预测输出并独立写查询 |
| 索引与优化 | 751 | B+ 树为何适合范围查询？哈希适合什么？复合／聚簇索引如何影响访问？选择率和连接顺序为什么重要？ | 能解释机制，并分析一条慢查询的可能原因 |
| 事务与恢复 | 751 | ACID 分别保护什么？隔离异常如何发生？锁为什么会死锁？WAL、undo、redo 有何分工？ | 能画两个事务的交错时序，说明故障前后状态 |
| 并发与分布式 | 711 | 线程与进程有何区别？互斥与条件变量如何协作？Lamport／向量时钟表示什么？CAP 的前提是什么？Paxos 的多数派解决什么？ | 能用消息时序说明安全性、活性和失败情形 |
| 批处理与数据流 | 752／753 | Map／Shuffle／Reduce 分别干什么？为什么不总能把数据放进内存？reservoir 如何保持公平抽样？ | 能手算一次 MapReduce 和抽样过程 |
| 概率数据结构 | 751／752／753 | Bloom filter 为什么可能误报？Misra–Gries、Count-Min、Count Sketch 有什么区别？ | 能说明所回答的问题、误差和适用条件 |
| ML 评估 | 722 | 如何分训练／验证／测试？交叉验证用来做什么？为何会过拟合？Precision／Recall／ROC／AUC 如何选择？ | 能解释为何某种评估会误导业务选择 |
| 检索与推荐 | 753，结合 752 | MinHash 如何关联 Jaccard？LSH 如何生成候选？协同过滤与矩阵分解如何工作？冷启动怎么办？ | 理解召回与排序、模型与指标的对应关系 |
| 实习项目 | 778 | 你负责什么？为什么这样设计？遇到什么问题？如何验证？有什么没做完？ | 给出真实的个人贡献、代码或交付物、结果与局限 |

## 中优先级：围绕岗位深化

- 数据工程：HDFS、Spark／MapReduce 的区别与课件覆盖边界、图数据模型、数据清洗、知识图谱。
- 后端／基础设施：流水线与 CPU Cache、分布式互斥、snapshot、Web cache、日志恢复的更细推演。
- 搜索／推荐／图算法：PageRank、社区检测、LSH 参数、Sketch 误差分析、上下文推荐与 Factorization Machines。
- DS：具体传统模型的假设与取舍、聚类评价、关联规则、解释与业务指标。
- AI 应用：结合 700、704、778 复习用户流程、POC、云责任边界、API 联调、风险、验收和采用障碍。
- 医疗数据：703 的实际资料缺口补齐后再确定专业题目；不把一般健康数据常识冒充已核实授课内容。

## 低优先级：暂不系统背诵

课程行政安排、讲师／企业介绍、展示稿里的历史金额和市场规模、软件界面按钮细节、与岗位无关的 XML 全语法／图查询形式证明、特定分布式 GC 算法长证明、学术诚信课程的技术题化整理。

低优先级指当前面试复习投入顺序，不代表内容不重要。已有期末复习稿可作导航，但不自动当标准答案：手写识别可能出错，部分自制总结还混入其他课程。

## 两条复习顺序

**软件开发／后端：**751 SQL → 索引／优化 → 事务／恢复 → 711 并发／分布式 → 752 数据管道 → 778 项目深挖。700／704 用于解释业务背景与工程取舍。

**DS／AI／推荐：**751 SQL → 722 数据与评估 → 753 推荐／相似检索 → 752 数据清洗／图／批流处理 → 711 可靠性基础 → 778 应用项目。推荐岗提前 753，数据工程岗提前 752。

无论走哪条路线，先把 778 项目事实整理成一页：不要等全部理论复习完才开始。更详细的阶段目标见 [roadmap](../review-plan/roadmap.md)。
