# 复习路线

本轮建立路线与检查点，不设未经用户确认的每日时间预算。完成一阶段的检查点后进入下一阶段，按岗位调整顺序。

| 阶段 | 核心材料 | 完成检查点 |
|---|---|---|
| 0：项目事实整理 | COMPSCI 778 的讲稿／计划，711 的项目自述 | 区分计划与完成；写清个人贡献、技术选择和待补证据；不编造性能数字 |
| 1：查询与建模 | COMPSCI 751 SQL、关系代数、ER | 用小样例写 JOIN、分组、子查询；解释键、约束和建模选择 |
| 2A：开发系统基础 | 751 索引／事务／恢复，711 线程／缓存／分布式 | 讲清一次查询、一次提交和一次故障的全过程 |
| 2B：DS 建模基础 | INFOSYS 722 流程、模型与评估 | 为一个分类问题定义数据切分、模型对照与指标，并解释过拟合 |
| 3：大规模数据 | 752 批流处理、清洗、图；753 LSH／Sketch | 为超出内存的数据选处理方式，说明空间／误差／计算代价 |
| 4：岗位专题 | 推荐岗选 753；数据工程选 752＋751；后端选 711＋751 | 形成至少一个可讲清原理和边界的专题小例子 |
| 5：综合演练 | 778 实习，704 咨询，700 创新／云／AI 采用 | 从业务问题讲到架构、数据、算法、可靠性、上线取舍和验证 |

软件开发优先 2A，DS／AI 优先 2B；无需两条路线一开始同时推进。

## 笔记写法

八股卡片建议：**问题 → 直觉 → 机制 → 小例子 → 反例／边界 → 资料来源**。每题只保留一份主卡片，多门课共享同一链接。

项目卡片建议：**背景 → 个人任务 → 关键选择 → 困难与解决 → 实际结果 → 局限与改进**。将“打算做”“已经做”“已经验证”分开。

## 资料缺口

- DIGIHLTH 703：待补实际课件／课堂笔记；现有简介不足以恢复完整教学结构。

- 岗位需要但材料未证明系统覆盖的内容，列为补课清单，不放进“已学课程”。
