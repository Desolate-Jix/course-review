↭ If a relation schema R can be reconstructed just by natural
join from a set of schemata R1, R2,..., Rn with all of them
subsets of R:
↭ then we observe a Join Dependency: JD(R, [R1, R2, ..., Rn])
↭ then we prefer decomposition of the table, a database with
relations based on R1, R2,..., Rn
↭ Note, this at first leads to a separate table for every attribute
dependent on a key.
↭ This is akin to a column store database.
↭ This is a valid and sometimes preferred design.
↭ Howver, tables with the same key can then be merged (joined)
on demand.
