# LAB｜同一份业务数据，用SQL和Python互相核对

先修：DB01–DB06、PY01–PY03。DB07/08未实测不影响先做本实验，但不能因此标记机制已掌握。

这是学习用小练习，分两个120分钟学习日完成；不规定个人项目开发内容。

## 第一次：查询与清洗

1. 按PY03规则读取dirty_orders.csv，记录保留/拒绝/重复及每行原因。
2. 把保留行与seed.sql中的订单逐id比较；原始数据应对应5条订单。
3. 独立写SQL：所有用户paid_count、paid_total、pending_count，保留无订单用户。
4. 用Python实现相同统计，确保同名用户不合并；结果按用户id排序。

## 第二次：验证与故障分析

1. SQL与Python结果逐字段比对，预期为 `(1,2,200,1),(2,1,50,0),(3,0,0,0),(4,0,0,0)`。
2. 手动给用户2追加新订单109、paid、75，同时在两边输入中加入；预测用户2变成2笔、125，再执行。
3. 加一条和109同id不同amount的导入行，证明被拒绝且不会覆盖已保留行。
4. 改坏一处过滤或分组，记录首次不一致、最小复现和修复理由。
5. 用2分钟讲清数据入口、质量规则、查询逻辑、验证方式和仍未覆盖的情况。

## 独立实现要求

不用新建网页或正式应用；两个小文件和一页记录足够。允许查语言API，不照抄参考实现。错误不是失败，能定位并验证修复是目标。

## 验收

结果与变式均一致；分类对账完整；没有误合并同名/同金额记录；能解释一个真实调试过程。任何一项未完成，记录具体卡点并续做，不宣称全模块通过。
