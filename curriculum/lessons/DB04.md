## 讲解与例题


### 1. 连接按条件匹配行

```sql
SELECT u.id AS uid,u.name,o.id AS oid,o.amount
FROM users u INNER JOIN orders o ON o.user_id=u.id
ORDER BY u.id,o.id;
```

对用户1有三个匹配，所以出现三次：101、102、105。用户2匹配103，用户4匹配104；用户3无匹配而消失。共5行，每行表示“用户与其某笔订单的一次匹配”。JOIN没有自动去重。

LEFT JOIN保留左表所有行：有匹配输出匹配，没有匹配则输出一行右侧字段全为NULL的记录。因此换成LEFT JOIN后共6行，其中用户3的oid和amount是NULL。

### 2. ON与WHERE的区别

如果要“保留全部用户，只连接paid订单”，应写：

```sql
SELECT u.id,o.id AS oid
FROM users u LEFT JOIN orders o
  ON o.user_id=u.id AND o.status='paid'
ORDER BY u.id,o.id;
```

结果是 `(1,101),(1,105),(2,103),(3,NULL),(4,NULL)`。paid条件限制哪些订单可以匹配。

若把paid条件移到WHERE，补出的NULL不满足条件，用户3和4会消失。两种写法表达不同需求。

### 3. 保留零订单用户后再统计

```sql
SELECT u.id,u.name,COUNT(o.id) AS n,
       COALESCE(SUM(o.amount),0) AS total
FROM users u LEFT JOIN orders o ON o.user_id=u.id
GROUP BY u.id,u.name ORDER BY u.id;
```

用户3的COUNT(o.id)是0；COUNT(*)却会把那条补出的行算作1。按name单独分组会把两位小王合并，也不是需求。

RIGHT JOIN与调换表顺序的LEFT JOIN可表达对应关系，本轮重点先掌握保留哪一侧。连接三张表时，要继续检查每一步是否引入一对多放大；不能靠SUM(DISTINCT amount)消除它，因为不同订单可能恰好同金额。
