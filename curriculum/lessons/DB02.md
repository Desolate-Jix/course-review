# DB02｜筛选、排序、NULL与结果粒度

先修：DB01。先修待验证时先做前节验收；通过可跳过重复讲解。

## 学完要能做到

独立写出筛选与稳定排序；能解释NULL如何影响WHERE，以及DISTINCT改变了什么。

## 讲解与例题


### 1. 先确定结果中的一行

“找已付款且金额至少100的订单”要求一行代表一笔订单，因此从orders出发：

```sql
SELECT id, user_id, amount
FROM orders
WHERE status = 'paid' AND amount >= 100
ORDER BY id;
```

结果是101和105，各100。数值相同不表示重复订单，它们的主键不同。

### 2. NULL为何不能用等号判断

NULL是未知或缺失。`city = NULL`不会得到TRUE，`city <> NULL`也不会。WHERE只保留条件为TRUE的行，所以寻找缺失城市要写：

```sql
SELECT id, name FROM users WHERE city IS NULL;
```

结果为用户3。`city <> 'Auckland'`也不会保留NULL城市，若要求“非奥克兰或城市未知”，需明确写 `city <> 'Auckland' OR city IS NULL`。

### 3. 排序与去重是不同操作

没有ORDER BY，输出顺序不作保证。只按amount排序时，同金额之间仍可任意排列；加id作为第二排序键获得稳定顺序。DISTINCT对选出的整组列去重：`SELECT DISTINCT name`有3行；`SELECT DISTINCT id,name`仍是4行。

不要为了解决不理解的多行结果随手加DISTINCT。先检查一行的含义与连接关系。
