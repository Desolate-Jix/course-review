## 讲解与例题


### 1. 存在性问题无需输出每次匹配

“查至少有一笔paid订单的用户”结果一行一个用户。可以先连接再去重，也可以直接问是否存在匹配：

```sql
SELECT u.id FROM users u
WHERE EXISTS (SELECT 1 FROM orders o WHERE o.user_id=u.id AND o.status='paid')
ORDER BY u.id;
```

结果1、2；用户1即使有两笔paid也只输出一次。这里子查询引用外层u.id，称为相关子查询。逻辑上对每个用户判断，实际执行可能由优化器改写，不能据语法推断一定逐行完整运行。

### 2. NOT EXISTS与NULL

NOT EXISTS用于不存在匹配。“没有paid订单”包括用户3和4。“没有任何订单”只有用户3，这两个问题不同。

`NOT IN`遇到子查询中的NULL有三值逻辑陷阱。比如判断 `3 NOT IN (1,NULL)`不能得到TRUE，因此可能丢失你期望的记录。用NOT EXISTS明确描述匹配不存在，并仍注意连接列的业务含义。

### 3. CTE把中间结果命名

```sql
WITH paid_totals AS (
  SELECT user_id,SUM(amount) AS total
  FROM orders WHERE status='paid' GROUP BY user_id
)
SELECT u.id,COALESCE(p.total,0) AS total
FROM users u LEFT JOIN paid_totals p ON p.user_id=u.id
ORDER BY u.id;
```

先把订单汇总成每用户一行，再与users连接，有利于检查结果粒度。CTE有助于表达和阅读，但不是自动加速开关；具体计划要看数据库。
