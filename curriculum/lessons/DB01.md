## 讲解与例题


### 1. 从“每行代表什么”开始

数据库把需要长期保存的事实放进表。表的列描述属性，一行描述某个对象或事件。先看[练习数据](../labs/README.md)：users记录用户，orders记录订单。说清楚一行代表什么，才能知道统计“行数”到底是在数用户还是订单。

小王有两个人，id分别为1和4。姓名不是可靠的唯一标识。主键 primary key 用来区分行，值必须唯一且非空。主键可以由多列组成，例如选课表的 `(student_id, course_id)`。

外键 foreign key 表达引用关系：orders.user_id引用users.id。在此模型中，每个订单必须属于一个存在的用户，但一个用户可以有零个、一个或多个订单。外键不会自动把两张表的结果拼出来，拼接需要查询。

### 2. 为什么要分表

假设把用户城市放进每条订单：小王搬家后，需要修改三条订单中的城市，漏改会造成相互矛盾。如果城市是“用户当前城市”，将它保存在users能避免这种重复。若要记录“下单时收货地址”，那是另一种历史事实，可以保存在订单或地址快照中。是否重复要结合业务含义判断。

多对多关系要增加关联表。例如学生可以选多门课，一门课有多个学生；选课表分别引用学生和课程，并用组合键阻止重复选同一门课。

### 3. 看懂第一条查询

```sql
SELECT id, name FROM users WHERE id = 1;
```

FROM指出数据来源；WHERE筛选符合条件的行；SELECT选择输出列。结果是 `(1, 小王)`。先按这种逻辑理解，物理执行顺序由数据库决定。

**常见混淆：**主键不是行号；删除其他行不会自动改变它。外键不要求唯一，否则会错误地限制一个用户只能有一笔订单。NULL表示缺失或未知，不能直接理解成0或空字符串。
