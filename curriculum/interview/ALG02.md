## Q1：HashMap和HashSet如何选择？查找一定是O(1)吗？

**中文参考回答：** HashMap保存键和值，适合次数或累计金额；HashSet只保存唯一元素，适合存在性。哈希查询通常在合理哈希分布下有常数级期望或平均性能，但不能不加条件地宣称所有情况最坏都是O(1)。还需把构建结构和额外空间算进去。

**英文回答提纲：** Use a map when each key needs an associated value, and a set for membership or uniqueness. Hash-based operations usually have constant expected performance under suitable assumptions.

**继续追问：** 同一个数出现三次，配对问题为什么不能只存Set？

**追问要点：** Set只知道存在，不知道还剩几个可消费的副本；需要频次Map。

**常见失分：** 不要把平均复杂度说成无条件最坏复杂度。

## Q2：配对计数为什么先查搭档再存当前元素？

**中文参考回答：** Map记录此前尚未配对的元素。读到x先查k-x是否还有正计数，有则消费一次，没有才存x，避免把同一个位置与自己配对。只有containsKey不够，因为键可能保留但计数已为0。

**英文回答提纲：** Check for an available complement before inserting the current value. This prevents pairing an element with itself. A stored key with a zero count is not an available match.

**继续追问：** k=6时，[3]和[3,3,3]分别有几对？

**追问要点：** 分别0对和1对；后者剩一个3。用这两个反例验证操作顺序。

**常见失分：** 不要忘记计数递减，也不要忽略k-x在题目范围外可能溢出的风险。
