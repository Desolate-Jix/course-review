## 本节必练

每次从下面两题选一题：先30–60秒给直接答案，再用1–2分钟补机制、例子与边界，最后回答追问。第二次学习/复习换另一题，不能永远只练熟悉题。

## Q1：NULL、0和空字符串有什么区别？为什么不能写city = NULL？

**中文参考回答：** NULL表示缺失或未知，0和空字符串是具体值。与NULL使用普通等号或不等号比较通常得到UNKNOWN；WHERE只保留TRUE，因此判断缺失应使用IS NULL。city不等于Auckland的查询不会自动保留未知城市，需求若包括未知，要明确加OR city IS NULL。

**英文回答提纲：** NULL represents missing or unknown information. Ordinary comparisons with NULL yield unknown, and WHERE keeps only true conditions. Use IS NULL to test for missing values.

**继续追问：** WHERE city <> 'Auckland'为什么漏掉用户3？

**追问要点：** 用户3城市为NULL，比较不是TRUE。改为非奥克兰或城市未知两个条件，才能覆盖需求。

**常见失分：** 不要把NULL直接视为0，也不要用= NULL判断。

## Q2：DISTINCT和ORDER BY有什么区别？为什么不能用DISTINCT随手修复重复？

**中文参考回答：** DISTINCT对输出的整组列去重；ORDER BY指定输出排序。按name去重会合并两个小王，而按id,name仍保留两个用户。多行可能是一对多关系的正常结果，先明确每行含义。需要确定顺序时写ORDER BY；并列值再加唯一排序键。

**英文回答提纲：** DISTINCT removes duplicate output rows; ORDER BY controls ordering. Repeated names may belong to different users, so removing them can lose valid information.

**继续追问：** 只按订单金额排序，为什么同金额订单顺序不稳定？

**追问要点：** 金额存在并列，数据库不保证并列行的相对顺序；加id作为第二排序键。

**常见失分：** “数据库默认按主键返回”“有多行就加DISTINCT”都不可靠。

- 4分钟：核对遗漏和错误，修改自己的提纲。
- 3分钟：用英语复述核心答案；保留不会说的关键词。
