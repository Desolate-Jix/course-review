## Q1：如何处理CSV中的缺失、类型错误、重复与冲突？

**中文参考回答：** 先定义字段与业务规则，再解析。非法类型、缺失必填、负金额、未知用户或非法状态应保留源行号和拒绝原因。按业务键区分同内容重复与不同内容冲突；不随意覆盖。解析、校验、分类和汇总分开，最后按行数、id和金额对账。

**英文回答提纲：** Define the schema and business rules first. Parse, validate and classify each row, retaining source locations and rejection reasons. Reconcile counts, identifiers and totals afterward.

**继续追问：** 如何验证清洗没有意外修改输入？

**追问要点：** 保存输入的独立副本或不可变表示，处理前后比较，并测试含嵌套对象的情况。

**常见失分：** 不要只删除异常而不记录，也不要只运行一个正常样例就说健壮。

## Q2：为什么用with和针对性的except？为什么不用split处理任意CSV？

**中文参考回答：** with让资源在离开代码块时得到管理，例如关闭文件。只捕获预期的数据解析异常，保留真正程序错误便于调试。CSV字段可能包含引号、逗号或换行，应用csv解析器；简单split逗号不能正确处理一般CSV格式。

**英文回答提纲：** A context manager handles resource cleanup. Catch expected exceptions rather than silently swallowing every error. Use a CSV parser because quoted fields can contain delimiters and newlines.

**继续追问：** except Exception: pass会掩盖什么？

**追问要点：** 可能把变量拼错、类型使用错误等程序问题也吞掉，让“程序有bug”看起来像“少了几条脏数据”。

**常见失分：** 不要声称捕获异常后程序就一定正确；还需要可观察的拒绝记录与对账。

## 按知识点补充的必修问答

### Q3：大文件为何不能总是read后全部放进内存？

**参考答案：** 峰值内存可能超过限制；逐行/分块读取减少驻留数据，但全局去重状态仍可能增长，需要外部存储或排序。

**追问与边界：** 流式读取能自动让所有处理O(1)空间吗？不能，集合、聚合和缓冲也占空间。

**英文关键词：** streaming, memory bound。

### Q4：重跑ETL怎样避免重复导入？

**参考答案：** 明确业务键、唯一约束、事务边界和处理批次，使用可重复执行的写入语义，并对账输入、拒绝、重复与输出。

**追问与边界：** 只记录已读行数够吗？不足以应对崩溃在写入与记录之间，应考虑原子提交。

**英文关键词：** idempotent ingestion, reconciliation。

## 15分钟课堂使用方式

- 3分钟：关闭答案，回答一题。
- 5分钟：用本节数据/代码补例子，接受一轮追问或反例。
- 4分钟：核对遗漏和错误，修改自己的提纲。
- 3分钟：用英语复述核心答案；保留不会说的关键词。

不额外延长学习日。实作仍在原练习时段完成，本页口述不能取代SQL/代码与结果验证。
