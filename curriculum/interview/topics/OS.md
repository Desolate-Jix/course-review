# OS｜操作系统、并发与Linux

阶段：B｜通用基础。先修：函数、内存引用；NET可并行学习。

先画状态和时间线，再把抽象概念连接到进程、内存和文件的可观测现象。

本页为可直接复习的题目、答案要点与追问边界；首次遇到概念，先读资料并完成例子。它不等同于已编写完整教科书讲义，也不代表已经掌握。题量随覆盖缺口增长，不设上限。

|题号|问题|参考答案要点|追问与边界|
|---|---|---|---|
|OS-01|进程、线程、协程怎样区别？|进程提供资源隔离边界；线程在进程内共享部分资源并有自己的执行状态；协程常由运行时调度，在挂起点切换。|协程是否天然多核并行？不是，并发与并行应分开。|
|OS-02|并发与并行有什么区别？|并发是在同一时期推进多个任务；并行是同一时刻实际执行多个任务。单核心也可并发。|I/O等待多时为何异步有用？等待时可推进其他工作，但不能自动加速CPU运算。|
|OS-03|上下文切换为什么有成本？|需保存恢复寄存器、调度状态等，可能影响缓存/TLB；进程与线程切换成本依系统和负载不同。|线程越多越快吗？不，切换、竞争和内存会抵消收益。|
|OS-04|用户态、内核态与系统调用是什么？|权限级别保护系统资源，程序通过系统调用请求文件、网络等受保护操作。|普通函数调用都切内核吗？不是，只有需要内核服务的路径才涉及相应切换。|
|OS-05|互斥锁、信号量、条件变量如何选择？|互斥锁保护临界区；信号量控制许可数量；条件变量配合锁等待共享谓词变化。|为什么等待条件常用while？被唤醒后条件可能又不成立，也可能虚假唤醒。|
|OS-06|原子性、可见性、有序性怎么区分？|原子性避免操作被拆开观察；可见性涉及写入传播；有序性涉及执行与观察顺序。同步机制需按语言内存模型解释。|单次赋值安全能保证先查再改安全吗？不能，复合操作仍可能竞态。|
|OS-07|死锁四条件与预防是什么？|互斥、持有并等待、不可剥夺、循环等待共同构成经典必要条件；统一加锁顺序可破坏循环等待。|死锁、饥饿、活锁一样吗？不，分别是互相阻塞、长期得不到资源、持续动作却无进展。|
|OS-08|虚拟内存、分页、缺页和TLB是什么？|虚拟地址经页表映射到物理页，TLB缓存映射；缺页触发内核处理，可能分配页或从存储加载。|申请很大地址空间等于已占同量物理内存吗？不一定，需区分虚拟与驻留内存。|
|OS-09|栈、堆与内存泄漏如何理解？|栈常保存调用帧，堆用于动态对象；生命周期与回收机制依语言。泄漏也包括不再需要却仍被引用的对象。|有GC能否泄漏？可以，缓存或监听器长期保留对象就可能导致增长。|
|OS-10|进程间通信有哪些方式？|管道、套接字、消息队列、共享内存等；选择依吞吐、隔离、同步与部署要求。|共享内存是否无需同步？不是，它只减少复制，仍需协调并发访问。|
|OS-11|阻塞、非阻塞、I/O多路复用怎么区别？|阻塞调用等待条件；非阻塞调用可立即报告未就绪；多路复用允许统一等待多个描述符就绪。|epoll就绪是否代表整个请求完成？不，程序仍需读取、处理部分数据并管理状态。|
|OS-12|Linux怎样定位CPU、内存、磁盘或网络瓶颈？|按现象查看进程、负载、驻留内存、I/O等待、文件/连接与日志；可用top/ps/free/vmstat/iostat/ss等工具交叉验证。|load高一定CPU满吗？不，某些不可中断等待也会计入，不能只看一个数字。|
|OS-13|文件描述符、权限与管道重定向有什么用？|描述符代表已打开资源；权限限制访问；重定向连接标准输入输出错误，管道把前一命令输出交给后一命令。|Too many open files先做什么？检查泄漏与并发规模，再判断限制调整，不能只无限提高上限。|

## 课堂验证

画两个线程同时执行“读计数→加1→写回”的交错，找出丢更新；再用锁覆盖完整读改写。观察一个本地进程的PID、线程数、内存和打开连接。

**预期与判分：** 无锁交错可把两次增加变为一次；锁必须覆盖完整临界区。观测只记录实际命令输出，不要求修改系统限制。

**英文关键词：** process, thread, coroutine, race condition, virtual memory, file descriptor。用“结论→机制→本例→边界”组织短答。
