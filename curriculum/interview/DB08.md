## Q1：ACID分别是什么？为什么用了事务还可能转账错误？

**中文参考回答：** 原子性保证整体提交或回滚；一致性需要约束与业务逻辑共同维护；隔离性规定并发可见性；持久性保护已提交结果。若收款账户不存在，UPDATE可能影响0行却不报错，单写BEGIN/COMMIT仍可能只扣款。因此还需校验业务条件和受影响行数。

**英文回答提纲：** ACID covers atomicity, consistency, isolation and durability. A transaction does not invent business rules: an update affecting zero rows may succeed, so validate the transfer conditions.

**继续追问：** 一致性是不是数据库自动保证所有业务都正确？

**追问要点：** 不是。数据库能执行声明的约束，应用仍要定义并检查完整业务不变量。

**常见失分：** 不要把一致性等同于“所有副本任何时候完全相同”，也不要把事务等同于业务必然正确。

## Q2：Read Committed和Repeatable Read有什么区别？超时后能直接重试吗？

**中文参考回答：** 以PostgreSQL为例，Read Committed通常每条语句获取新的已提交快照，事务内两次读取可能不同；Repeatable Read使用事务快照，两次读取可保持一致，但不等于排除所有业务并发异常。请求超时不能证明未提交，重试需查询确认或幂等设计。

**英文回答提纲：** In PostgreSQL, Read Committed can observe a newer committed value in a later statement. Repeatable Read uses a transaction snapshot. A timeout leaves the commit outcome uncertain, so retries need care.

**继续追问：** 为什么提交不要求所有数据页马上写回最终位置？

**追问要点：** WAL等恢复机制可先按规则保证日志持久，再在需要时恢复数据页。具体保证受数据库配置影响。

**常见失分：** 不要把其他数据库隔离细节直接套过来，也不要说“超时就一定回滚”。

## 按知识点补充的必修问答

### Q3：脏读、不可重复读、幻读、丢失更新有什么区别？

**参考答案：** 分别涉及未提交数据、同一行值变化、条件结果集合变化和并发写覆盖。应给时间线说明，不能只背四个词。

**追问与边界：** 隔离级别相同是否实现和异常完全相同？不是；本课PostgreSQL与MySQL需分开。

**英文关键词：** dirty read, lost update。

### Q4：乐观锁与悲观锁如何保护更新？

**参考答案：** 乐观方案以版本条件更新并检查影响行数；悲观方案先锁定必要记录。二者都需事务边界和失败处理。

**追问与边界：** 版本更新影响0行能当成功吗？不能，应重读、冲突返回或有界重试。

**英文关键词：** optimistic concurrency, row lock。

### Q5：死锁怎样产生、怎样减少？

**参考答案：** 事务互相等待对方持有资源会形成环；统一访问顺序、缩短事务、减少锁范围可降低风险，受害事务需正确重试。

**追问与边界：** 加更多锁总能解决吗？不，可能扩大等待与死锁风险。

**英文关键词：** deadlock, lock ordering。

### Q6：隔离级别和持久性怎样按产品回答？

**参考答案：** 先说明数据库版本。PostgreSQL默认RC，MySQL InnoDB默认RR；WAL/redo及提交刷盘策略要按产品解释。

**追问与边界：** 提交响应丢失能认为没提交吗？不能；结果未知时应查询业务状态或用幂等键恢复。

**英文关键词：** isolation, durability。
